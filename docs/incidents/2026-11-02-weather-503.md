# Incident 2026-11-02: weather API HTTP 503, one poll lost

Status: closed (no recovery possible by design)
Detected: 2026-11-03 10:52 Asia/Tashkent, daily coverage check
Collector: `0.1.0+0726522` (tag `cp1-submission`), database `data/assessed.db`

## What happened
The poll started at 2026-11-02T15:05Z (20:05 Asia/Tashkent) received HTTP 503 from the
Open-Meteo weather endpoint for all eight cities. Each request was retried three times
with exponential backoff (2, 4, 8 s) and then recorded as `failed` (`collection_runs`,
run_id 321, 323, ..., 335; `retry_count = 3`; latency 1.0 to 6.1 s per attempt chain).
The failed requests span 15:05:01Z to 15:07:31Z (start times). The air-quality endpoint
answered normally. The next poll (16:05Z) and all later polls succeeded (16/16 requests
per hour).

## Effect on the data
- 8 city-rows are missing (one per city). The valid time 15:00Z is a native three-hourly
  CAMS step, so each city has one fewer native row (10 instead of 11 by 2026-11-03 10:05).
- The eight air-quality responses of that poll are stored unchanged in `raw_responses`
  (status `success`), but no `observations` row exists because the weather half is missing.
- Origins whose t, t-3 h, t-6 h or t+6 h lands on 15:00Z lose eligibility in the analysis.
  The exact count of eligible pairs is reported after lag construction, separately from
  collected rows (approval email, 2026-10-28).
- Coverage to 2026-11-03 10:05 (35 polls): 34 successful, 272 of 280 rows (97.1%).
  First full day (2 Nov, 24 polls): 23 of 24 polls, 184 of 192 rows (95.8%).

## Decision
- No back-fill: missed times stay gaps (collection plan; no catch-up run).
- The collector was not changed during the assessed window (decision 0007).
- The unpaired air-quality responses are not turned into observations. Whether they could be
  used for PM2.5 lags or targets would change the protocol's definition of a valid row, so it is
  not done unless agreed in writing with the Module Leader.
- The record is kept in the coverage section of the final report.

## What the audit trail showed (works as designed)
Retry with backoff, `failed` status with `HTTP 503`, raw error bodies hashed (`verify`:
560 responses, 0 mismatches), the other seven poll-hours unaffected, no quarantine.

## Limitation for the report
The retry window (14 s of backoff) is short relative to a service outage of a few minutes.
A later retry within the same hour would have recovered this poll. Listed as an improvement
for a longer study; not applied to the assessed collector.
